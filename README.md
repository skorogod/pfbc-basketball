# PFBC Telegram Bot

Бот для администрирования процессов баскетбольного клуба PFBC.
Требования — в [docs/technical_specification.md](docs/technical_specification.md).

**Реализовано (этапы 0–1 ТЗ):** контроль доступа по членству в группе состава (ФТ-0), онбординг и регистрация (ФТ-1), расписание тренировок и утренний опрос (ФТ-2), дежурные по залу (ФТ-3), поздравления с днём рождения (ФТ-6), журнал событий с проверкой пересечений, публикацией и напоминаниями (ФТ-9), администрирование (ФТ-10).
Схема БД уже содержит таблицы следующих этапов (матчи ABL, оплата, праздники).

## Стек

Python 3.12 · aiogram 3 · PostgreSQL 16 · SQLAlchemy 2 (async) + Alembic · pydantic 2 · APScheduler · Docker Compose + Caddy.

## Локальная разработка

```bash
python3.12 -m venv venv && . venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env                       # BOT_TOKEN, ADMIN_TG_IDS, DATABASE_URL; BOT_MODE=polling

docker compose up -d postgres              # или свой PostgreSQL
alembic upgrade head

python -m pfbc_bot.main_web                # бот (polling)
python -m pfbc_bot.main_worker             # планировщик — в отдельном терминале
```

Проверки (то же самое запускает CI):

```bash
ruff check src tests && ruff format --check src tests
mypy
pytest            # интеграционным тестам нужен Docker (testcontainers) или TEST_DATABASE_URL
```

## Развёртывание на VPS

1. DNS-запись домена указывает на VPS; открыты порты 80 и 443 (ufw: 22, 80, 443).
2. `cp .env.example .env` — заполнить `BOT_TOKEN`, `ADMIN_TG_IDS`, `DOMAIN`, `WEBHOOK_BASE_URL=https://<DOMAIN>`, `POSTGRES_PASSWORD`, `WEBHOOK_PATH_SECRET` и `WEBHOOK_SECRET_TOKEN` (`openssl rand -hex 32`).
3. `docker compose up -d --build`.
   Порядок запуска: `postgres` → `migrate` (`alembic upgrade head`) → `web` (регистрирует webhook) и `worker`; `caddy` выпускает TLS-сертификат; `backup` раз в сутки делает `pg_dump` в `./backups` с хранением 14 дней.
4. Проверка: `curl https://<DOMAIN>/healthz` → `{"status": "ok"}`.

Копию `./backups` вне VPS нужно настроить отдельно (например, `rclone` по cron).
⚠️ Перед запуском решите вопрос хранения персональных данных (152-ФЗ, ч. 5 ст. 18) — см. раздел 6 ТЗ.

## Подключение группы состава

1. Добавьте бота в группу состава (супергруппа с включёнными топиками) и **сделайте его администратором** — иначе Telegram не присылает события вступления и выхода участников.
2. Админ (ID из `ADMIN_TG_IDS`) сначала нажимает `/start` в личке бота — туда будут приходить ответы.
3. Разовая привязка в группе (бот удаляет эти сообщения и отвечает в личку):
   - `/bind Взрослые` — создать состав и привязать к нему группу;
   - в каждом нужном топике — `/bind_topic trainings`, `/bind_topic games`, `/bind_topic greetings`, `/bind_topic general` (также доступен `payments`).
4. Всё остальное — в личке бота: `/roles` → состав → участник → «Тренер ✓» / «Капитан ✓».
   Дополнительных админов назначает любой админ через `/admins` (только из участников составов). Админы из `ADMIN_TG_IDS` — «корневые»: снимаются только правкой `.env` и перезапуском.
5. При вступлении в группу бот молчит. Тренер или капитан берёт ссылку командой `/invite` и пересылает новичку. Тем, кто был в группе до подключения бота, достаточно написать боту `/start` — бот проверит членство через Telegram.
6. Тренер в личке бота: `/schedule` → «Добавить» → `Пн 19:00 90 Зал школы №5`.

Настройки — в личке у админа: `/settings` (выбор состава или «Глобальные») и `/set <ключ> <значение>`, например `/set training_poll_time 08:30`, `/set duty_newcomer_grace_days 14`, `/set features.birthdays false`. Если ключ относится к составу, бот спросит состав; глобальные ключи (`inactive_retention_days`) применяются сразу.

## Команды

| Кто | Команды (в личке бота) |
|---|---|
| Все участники | `/start`, `/help`, `/profile`, `/events`, `/delete_me`, `/cancel`; дежурный — кнопка «Не могу дежурить» в личке |
| Тренер | `/schedule`, `/trainings` (отмена, перенос), `/training_add`, `/attendance`, `/duty`, `/event_add`, `/event_del`, `/invite` |
| Капитан | `/attendance`, `/duty` (замена и ручной выбор дежурных), `/event_add`, `/event_del`, `/invite` |
| Админ | всё перечисленное, а также `/squads`, `/roles`, `/admins`, `/settings`, `/set`; в группе (разово) — `/bind`, `/bind_topic` |

Дежурства: в группе — одно объявление без кнопок, бот редактирует его при заменах. Дежурный получает назначение в личку, капитан — сводку с кнопками управления. Каждое изменение подтверждается вторым нажатием.

`/event_add` спрашивает длительность события и проверяет пересечения с тренировками, матчами и другими событиями состава: при конфликте показывает предупреждение (продолжить / изменить время / отмена). В конце можно опубликовать событие в группе — в топике «Игры» для матчей и турниров, иначе в общем.

## Архитектура

```
src/pfbc_bot/
  bot/            aiogram: роутеры, AccessMiddleware, клавиатуры, FSM-хранилище в PostgreSQL
  services/       бизнес-логика, не зависит от aiogram; Notifier (ports.py) — порт к Telegram
  domain/         чистые функции и перечисления: выбор дежурных, даты и напоминания
  repositories/   SQL-доступ; UnitOfWork — транзакция и набор репозиториев
  db/models/      ORM-модели SQLAlchemy (схема данных)
  schemas/        pydantic: DTO между слоями, валидация ввода, типизированные настройки
  integrations/   реализации портов (TelegramNotifier)
  scheduler/      задачи worker-а
  main_web.py     webhook/polling        main_worker.py   планировщик
```

- Хэндлеры тонкие и вызывают сервисы. Права проверяются в сервисах, поэтому их не обойти из другого интерфейса.
- Задачи планировщика — «тики»: каждый раз смотрят в БД, что пора сделать. Повторной отправки не бывает благодаря уникальному ключу в `reminder_log`, рестарт worker-а безопасен.
- Как добавить функцию (например, матчи ABL на этапе 2): модель/миграция → репозиторий → сервис (+ при необходимости порт для внешнего источника в `services/ports.py` и адаптер в `integrations/`) → роутер → задача в `scheduler/jobs.py` → регистрация в `services/container.py` и `bot/factory.py`.
