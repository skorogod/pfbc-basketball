# PFBC Telegram Bot

Бот для администрирования процессов баскетбольного клуба PFBC.
Требования — в [docs/technical_specification.md](docs/technical_specification.md).

**Реализовано:** контроль доступа по членству в группе состава (ФТ-0), регистрация с телефоном (ФТ-1), расписание тренировок и опросы, в том числе вручную (ФТ-2), дежурные по залу (ФТ-3), матчи ABL из mtgame.ru с постом и опросом в топике `match` и запросом тренеру к четвергу, если матч не найден (ФТ-4), разбор игры с предложением после матча (ФТ-5), поздравления с днём рождения (ФТ-6), ежемесячный опрос о квитанциях за тренировки (ФТ-8, частично), сбор денег за игру по заявке с уведомлением тренеру «состав набран» (ФТ-8a), журнал событий: матчи, турниры (дни или сезон, дивизион, стоимость игры, привязка матчей), собрания, перенос и публикация с опросами (ФТ-9), права ролей, карточка участника и администрирование (ФТ-10).
**Не реализовано:** поздравления с праздниками (ФТ-7), приём квитанций ботом и персональные запросы (ФТ-8), редактирование шаблонов текстов. Бэклог и результаты ревью — в разделе 8 ТЗ.

## Стек

Python 3.12 · aiogram 3 · PostgreSQL 16 · SQLAlchemy 2 (async) + Alembic · pydantic 2 · APScheduler · Docker Compose + Caddy.

## Локальная разработка

```bash
python3.12 -m venv venv && . venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env                       # BOT_TOKEN, ADMIN_TG_IDS, DATABASE_URL; BOT_MODE=polling

docker compose up -d postgres              # или свой PostgreSQL
alembic upgrade head

python -m pfbc_bot.main                    # бот (polling)
python -m pfbc_bot.main_worker             # планировщик — в отдельном терминале
```

Зависимости зафиксированы в lock-файлах: `requirements.lock` — для бота, точные версии с
хешами (образ ставит их с `--require-hashes`); `requirements-dev.lock` — те же версии плюс
инструменты разработки, без хешей (CI). Точно как в CI:
`pip install -r requirements-dev.lock && pip install --no-deps -e .`.
После изменения зависимостей в `pyproject.toml` lock-файлы пересобираются:

```bash
pip-compile --generate-hashes --strip-extras --allow-unsafe -o requirements.lock pyproject.toml
pip-compile --strip-extras --allow-unsafe --extra dev -o requirements-dev.lock pyproject.toml
```

Проверки (то же самое запускает CI):

```bash
ruff check src tests && ruff format --check src tests
mypy
pytest            # интеграционным тестам нужен Docker (testcontainers) или TEST_DATABASE_URL
```

## Развёртывание на VPS

1. DNS-запись домена указывает на VPS; открыты порты 80 и 443 (ufw: 22, 80, 443).
2. `cp .env.example .env` — заполнить `BOT_TOKEN`, `ADMIN_TG_IDS`, `DOMAIN`, `WEBHOOK_BASE_URL=https://<DOMAIN>`, `POSTGRES_PASSWORD`, `WEBHOOK_PATH_SECRET` и `WEBHOOK_SECRET_TOKEN` (`openssl rand -hex 32`).
3. Убедитесь, что в `.env` стоит `BOT_MODE=webhook` (в примере — `polling` для разработки; в режиме polling бот работает, но Caddy и вебхук не используются, в логе будет предупреждение).
4. `docker compose up -d --build`.
   Порядок запуска: `postgres` → `migrate` (`alembic upgrade head`) → `bot` (регистрирует webhook) и `worker`; `caddy` выпускает TLS-сертификат; `backup` раз в сутки делает `pg_dump` в `./backups` с хранением 14 дней.
5. Проверка: `curl https://<DOMAIN>/healthz` → `{"status": "ok"}`.

Копию `./backups` вне VPS нужно настроить отдельно, иначе бэкап погибнет вместе с сервером. Например, `rclone` по cron на хосте: `0 5 * * * rclone sync /opt/pfbc/backups remote:pfbc-backups`.
⚠️ Перед запуском решите вопрос хранения персональных данных (152-ФЗ, ч. 5 ст. 18) — см. раздел 6 ТЗ.

## Подключение группы состава

1. Добавьте бота в группу состава (супергруппа с включёнными топиками) и **сделайте его администратором** — иначе Telegram не присылает события вступления и выхода участников. Дайте ему право «Закреплять сообщения»: пост о событии закрепляется (тихо) и открепляется после события, при переносе или удалении.
2. Админ (ID из `ADMIN_TG_IDS`) сначала нажимает `/start` в личке бота — туда будут приходить ответы.
3. Разовая привязка в группе (бот удаляет эти сообщения и отвечает в личку):
   - `/bind Взрослые` — создать состав и привязать к нему группу;
   - в каждом нужном топике — `/bind_topic trainings`, `/bind_topic match`, `/bind_topic greetings`, `/bind_topic teambuilding` (собрания команды), `/bind_topic general` (также доступен `payments`). Если для сообщения свой топик не назначен, бот пишет в `general`, а без него — в основной раздел группы.
4. Всё остальное — в личке бота: `/roles` → состав → участник → «Тренер ✓» / «Капитан ✓».
   Дополнительных админов назначает любой админ через `/admins` (только из участников составов). Админы из `ADMIN_TG_IDS` — «корневые»: снимаются только правкой `.env` и перезапуском.
5. При вступлении в группу бот молчит. Тренер или капитан берёт ссылку командой `/invite` и пересылает новичку. Тем, кто был в группе до подключения бота, достаточно написать боту `/start` — бот проверит членство через Telegram.
6. Тренер в личке бота: `/schedule` → «Добавить» → `Пн 19:00 90 Зал школы №5`.

Настройки — в личке у админа: `/settings` (выбор состава или «Глобальные») и `/set <ключ> <значение>`, например `/set training_poll_time 08:30`, `/set duty_newcomer_grace_days 14`, `/set features.birthdays false`. Если ключ относится к составу, бот спросит состав; глобальные ключи (`inactive_retention_days`) применяются сразу.

## Команды

Каждый видит в меню Telegram и в `/help` только доступные ему команды — набор определяется правами ролей (раздел 3 ТЗ). Права ролей меняет админ командой `/permissions`; «Сбор денег за игру» закреплён за тренером.

| Кто (по умолчанию) | Команды в личке бота |
|---|---|
| Все участники | `/start`, `/help`, `/profile` (ФИО, дата рождения, mtgame, телефон), `/events`, `/attendance` (кто придёт), `/delete_me`, `/cancel`; дежурный — кнопка «Не могу дежурить» |
| Капитан | `/poll` (опрос на тренировку вручную), `/duty` (дежурства: замена, ручной выбор), `/event_add` и перенос / отмена кнопками в `/events` — только собрания, `/invite` |
| Тренер | `/schedule`, `/trainings` (отмена, перенос), `/training_add`, `/poll`, `/event_add`, перенос и отмена кнопками в `/events` (матчи, турниры, разборы, сборы, собрания), `/review`, `/tournaments` (привязка матчей, название, дивизион, стоимость игры), `/game_pay` (сбор денег за игру: заявка до 12 игроков → сумма → реквизиты; когда «Буду (игрок)» отметили 10 — кнопка «Начать сбор» приходит сама: заявка → «Готово. Начать сбор», недостающие стоимость игры и реквизиты спрашиваются только если их нет), `/receipts` (опрос о квитанциях за тренировки), `/invite`; реквизиты для сбора (до 5: добавить, изменить, удалить) — в `/profile` → «Реквизиты» |
| Админ | всё перечисленное, а также `/squads`, `/roles` (назначение ролей; по нажатию на участника — его карточка), `/member` (карточка участника: профиль, реквизиты — только просмотр), `/admins`, `/permissions`, `/settings`, `/set`; в группе (разово) — `/bind`, `/bind_topic` |

Любая команда, набранная посреди незавершённого ввода, прерывает его — как `/cancel`.

Дежурства: в группе — одно объявление без кнопок, бот редактирует его при заменах. Дежурный получает назначение в личку, капитан — сводку с кнопками управления. Каждое изменение подтверждается вторым нажатием.

`/event_add` спрашивает длительность события и проверяет пересечения с тренировками, матчами и другими событиями состава: при конфликте показывает предупреждение (продолжить / изменить время / отмена). В конце показывает сводку введённого и предлагает опубликовать событие в группе — в топике match для матчей, турниров и разборов, собрания — в топике `teambuilding`, остальное — в общем; к матчу, турниру и разбору добавляется опрос участия. Если публикация не удалась, бот так и сообщает. `/events` показывает каждое событие отдельным сообщением; у тех, которыми можно управлять, — кнопки «Перенести» и «Отменить» (обе через подтверждение). Перенос: команда получает сообщение о переносе, опрос публикуется заново, напоминания пересчитываются. Опросы участия закрываются, когда событие начинается, а опрос участия в матче — ещё и при публикации сбора денег за него: состав фиксируется. Платят только игроки заявки, выбранной тренером (до `game_roster_max`, по умолчанию 12); в топик match уходит «Состав на матч», пост сбора и опрос «Оплатил». Сообщение тренерам «Буду (игрок)» отметили N» — одно, с `game_payment_squad_size` (по умолчанию 10, 0 — выключить); дальше число обновляется в нём же, без новых уведомлений.

Напоминания об оплате (игры и квитанции): количество и интервал задаются для состава — `game_payment_reminder_count` / `game_payment_reminder_interval_hours` и `receipt_reminder_count` / `receipt_reminder_interval_hours` (по умолчанию одно напоминание в срок; интервал 24 ч). С 00:00 до 08:00 бот не напоминает — переносит на 08:00. Итог «оплатили N из M» не присылается: он виден в опросе. Остановить напоминания — кнопка «🏁 Завершить сбор» (для игры — в сводке `/attendance` по матчу, для квитанций — в `/receipts`): бот закрывает опрос в группе.

Квитанции за тренировки: раз в месяц (`receipt_poll_day`, по умолчанию 1-го, в `receipt_poll_time`, 10:00) бот публикует в топике `payments` (нет его — в `general`) просьбу прислать тренеру квитанцию и опрос «Отправил / Отправлю позже». Тренер может запустить опрос раньше командой `/receipts` и задать свой срок; тогда по расписанию в этом месяце опрос не публикуется, а повторный `/receipts` показывает, кто отметился. Срок по умолчанию — `receipt_deadline_hours` (24 ч). После срока бот напоминает в личку всем участникам, кроме тренеров, кто не отметил «Отправил» (не дошло — упоминание в группе). Отключить: `/set features.receipt_reminders false`.

## Архитектура

```
src/pfbc_bot/
  bot/            aiogram: роутеры, AccessMiddleware, клавиатуры, FSM-хранилище в PostgreSQL
  services/       бизнес-логика, не зависит от aiogram; Notifier (ports.py) — порт к Telegram
  domain/         чистые функции и перечисления: выбор дежурных, даты и напоминания
  repositories/   SQL-доступ; UnitOfWork — транзакция и набор репозиториев
  db/models/      ORM-модели SQLAlchemy (схема данных)
  schemas/        pydantic: DTO между слоями, валидация ввода, типизированные настройки
  integrations/   реализации портов (TelegramNotifier)
  scheduler/      задачи worker-а
  main.py         webhook/polling        main_worker.py   планировщик
```

- Хэндлеры тонкие и вызывают сервисы. Права проверяются в сервисах, поэтому их не обойти из другого интерфейса.
- Задачи планировщика — «тики»: каждый раз смотрят в БД, что пора сделать. Повторной отправки не бывает благодаря уникальному ключу в `reminder_log`, рестарт worker-а безопасен.
- Как добавить функцию (например, матчи ABL на этапе 2): модель/миграция → репозиторий → сервис (+ при необходимости порт для внешнего источника в `services/ports.py` и адаптер в `integrations/`) → роутер → задача в `scheduler/jobs.py` → регистрация в `services/container.py` и `bot/factory.py`.
